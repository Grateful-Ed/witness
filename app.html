Connection — the client’s WMS

Witness does not replace the warehouse system. It connects to it: acts travel through the host’s own interfaces (never its database), and the host stays the system of record. This is the connection Witness is currently running on.

Host API key

The credential this connection presents to the host. It is entered hidden, and after saving it is only ever shown as a mask.

In this demonstration build the key is kept with the application’s configuration. A production deployment keeps it in the client’s own server-side secret store — never in the shared record, never on a screen.

Ontology — what the building has learned

The ontology holds what this building is, what its words mean, and how this site runs. When the system meets a shape it cannot name, it learns it as a concept — detected, then described by the AI, then settled by a person. Settling happens here; it is the same writer the console uses, through a second door.

Site — this client’s configuration

How this site runs is the client’s to settle, and it lives here — in the application, not in the WMS.

The site’s operating choices — what a completion must mean here, how concrete it has to be, the knobs a manager should own — land on this screen as the configuration layer is built. Nothing here pretends to work before it does.
